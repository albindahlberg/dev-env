# codex

Portable `~/.codex` config, mirroring `claude/`. `../install.sh` links the
tracked parts into `~/.codex/`.

Excluded (machine-local / secret): `config.toml.bak-*`, `history.jsonl`,
`sessions/`, `logs_*.sqlite`, `state_*.sqlite`, `memories*`, caches.

`skills/` holds only symlinks into `../skills/<category>/<name>` (shared with
`claude/`, see `../AGENTS.md`) — `git/` (commit, worktree),
`github/` (pr, issue, gh-stack), `workflow/` (skewer, skewer-w-docs, intent, spec, build, show-me, herdr), `design/` (frontend taste skills, vendored from Leonxlnx/taste-skill), `writing/` (unslop),
`dotfiles/` (config-sync), `project-setup/` (blueprint). The category is a repo-side grouping only; the
symlinks here stay flat.

Codex-only skills (`caveman`, `grill-me`, `tdd`) are real dirs in `skills/`
here, not in the shared tree: Claude gets tdd/grilling from the mattpocock
marketplace plugin, so a shared copy would duplicate it. `~/.codex/skills/synced`
is Codex's cloud-synced skill cache and stays machine-local.

`hooks/secret-guard.sh` symlinks into `../hooks/` (also shared with `claude/`).
`hooks/mlflow-codex-notify.sh` is codex-only (no `claude/` equivalent — Claude
Code tracing goes through the native `mlflow-tracing` marketplace plugin
instead), so it stays here rather than in the shared `../hooks/` dir.

`config.toml` is seeded, not linked: Codex rewrites it (project trust list,
MCP servers, model/auth settings) per machine, so `install.sh` only copies it
in if `~/.codex/config.toml` doesn't exist yet. It deliberately omits
machine-specific bits (project trust list, MCP server keys, notify hooks) —
add those locally after seeding.

`hooks.json` is seeded the same way (herdr and other integrations append to
it). It registers `secret-guard.sh` and the herdr hook; `install.sh` warns
(`HOOKS`) when the live file's hooks drift from it, so merge new ones by hand.

`herdr-agent-state.sh` is codex-specific (generated by
`herdr integration install codex`, content differs from claude's copy) and
lives directly under `~/.codex/`, not `~/.codex/hooks/` — claude's
equivalent is tracked separately under `../claude/hooks/`.
