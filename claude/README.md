# claude

Portable `~/.claude` config. `../install.sh` links the tracked parts into `~/.claude/`.

Excluded (machine-local / secret): `.credentials.json`, `history.jsonl`,
`sessions/`, `projects/`, `tasks/`, `teams/`, `file-history/`, caches.

`skills/` here holds only symlinks into `../skills/<category>/<name>` (shared
with `codex/`, see `../AGENTS.md`) — `git/` (commit, worktree),
`github/` (pr, issue, gh-stack), `workflow/` (skewer, skewer-w-docs, intent, spec, build, show-me, herdr), `design/` (frontend taste skills, vendored from Leonxlnx/taste-skill), `writing/` (unslop),
`dotfiles/` (config-sync), `project-setup/` (blueprint). The category is a repo-side grouping only; the
symlinks here stay flat.

`hooks/secret-guard.sh` symlinks into `../hooks/` (also shared with `codex/`).

`settings.json` registers plugin marketplaces but leaves every plugin off by
default (`enabledPlugins` values are `false`). Enable what you want per machine —
those toggles stay local.

## MLflow tracing

Traces go to a local MLflow server (docker, `http://localhost:5000`,
experiment `agent-traces`) via the `mlflow-tracing@mlflow-plugins` plugin.
The plugin records only the raw working directory, so:

- `hooks/mlflow-tag-repo.sh` (Stop hook) tags each trace with `repo`
  (`owner/name` from the git origin, so worktrees and subdirs collapse into
  one). Slice with `tags.repo = 'kardapp/gdr'` in the UI or API.
  `--backfill` tags every untagged trace.
- `hooks/mlflow-feedback.sh` (UserPromptSubmit hook) logs feedback on the
  previous turn's trace: a `+1 [note]` / `-1 [note]` prompt logs
  `user_rating` and never reaches the model; a prompt opening with a
  correction (`no`, `wrong`, `revert`, `try again`, ...) logs `corrected`.
- `scripts/mlflow-backup.sh` snapshots the DB and artifacts into
  `~/mlflow-local/backup/<weekday>/`, so there are 7 rotating snapshots.

Per-machine setup that isn't tracked. Add the MCP server so Claude can query
its own traces (lives in `~/.claude.json`):

    claude mcp add -s user mlflow -e MLFLOW_TRACKING_URI=http://localhost:5000 \
      -- uv run --with "mlflow[mcp]==3.16.1" mlflow mcp run

Add a cron job that catches traces the Stop hook missed (e.g. the subagent
traces written after the last Stop) and takes the backup:

    0 * * * * bash $HOME/.claude/hooks/mlflow-tag-repo.sh --backfill >/dev/null 2>&1; $HOME/.claude/scripts/mlflow-backup.sh >/dev/null 2>&1

Pin the MCP version to the server's version. Beyond `+1`/`-1`, rate in the
UI's trace view, or ask Claude to log feedback through the MCP server.
Once enough are labelled, run `mlflow.genai.evaluate` with a judge over them.

`hooks/herdr-agent-state.sh` is generated by `herdr integration install claude`
but tracked here and linked into each profile's `hooks/`. herdr writes through the
link, so re-running the install after a herdr update shows up as a repo diff.
